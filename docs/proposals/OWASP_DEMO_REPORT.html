How remediation data is delivered

Every OWASP finding carries three remediation fields emitted by create_finding(), matching the pattern the existing 51 service-level checks already use:

  • Finding_Details — the exact mis-configuration observed, with resource identifiers (guardrail ID, KB name, log-group name).
  • Resolution — a prescriptive, step-by-step fix, often naming the specific API call (logs:PutRetentionPolicy), field (sensitiveInformationPolicy.piiEntities), or parameter (inputStrength=HIGH) to change.
  • Reference — a deep link into the relevant AWS documentation page, rendered as an icon button in the Docs column so reviewers can jump straight to the docs.

This is identical to the contract the existing BR-/SM-/AC- checks honor, so the new OWASP rows blend into the same findings table without any UI-template work beyond adding the Compliance column.
